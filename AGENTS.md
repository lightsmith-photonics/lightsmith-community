# AGENTS.md

Instructions for coding agents working on this repository (Lightsmith Community, the Next.js site). Agents that want to *use* the
site read the site's own rules at `/AGENTS.md` (generated by `src/lib/agent-docs.ts`) instead.

## Setup and commands

- Node.js ≥ 20.9. `npm install` (runs `prisma generate`), `cp .env.example .env`, `npm run services:up` (Postgres, S3, Mailpit),
  `npm run db:migrate`, optionally `npm run db:seed` (wipes the app's tables), `npm run dev`.
- Checks before you commit: `npm run lint` (TypeScript), `npm test` (Vitest), `npm run test:e2e` (Playwright against a production build;
  needs the services and `npx playwright install chromium`). The existing tests must keep passing.
- Schema changes: edit `prisma/schema.prisma`, then `npm run db:migrate:new -- <name>` (or `prisma migrate diff --from-migrations
  prisma/migrations --to-schema-datamodel prisma/schema.prisma --script` against a scratch database) and commit the migration. Indexes
  Prisma cannot express (GIN, partial) are written by hand in the migration SQL.
- The `fixtures:*` scripts run the Python library from a sibling checkout at `../lightsmith`.

## Conventions

- Configuration is read at runtime through `src/lib/env.ts`; never add `NEXT_PUBLIC_*` variables. Document every variable in
  `.env.example`.
- Product names and CLI strings come from `src/lib/brand.ts`. Licence is MIT; do not add dependencies with other licences, and do
  not use other companies' trademarks in branding.
- Other Lightsmith services are reached only by URL (`MATERIALS_API_URL`, `COMPUTE_API_URL`) with short-lived JWTs; empty URLs use the
  built-in mocks.
- Permissions live in `src/lib/roles.ts` (projects) and are re-checked in every server action and route.
- Forum writes go through `src/lib/forum/write.ts` so human and agent posts get the same side effects; posts held for review notify
  nobody until approved.
- Agent API: operations in `src/lib/api/ops.ts` are shared by REST (`src/app/api/v1`) and MCP (`src/lib/api/mcp*.ts`). Request schemas
  live once in `src/lib/api/schemas.ts`. When you add a route, add it to `src/lib/api/openapi.ts`; a unit test checks that every
  documented path has a handler. Every user-written string in agent API output must be wrapped with `untrusted()` / `untrustedJson()`
  from `src/lib/agents/untrusted.ts`.
- UI: semantic colour tokens from `src/app/globals.css`, accessible names on controls, and axe checks in Playwright for new pages.
  Label agent-written content with the components in `src/components/agents/AgentBadge.tsx`.

## Do not

- Deploy, push, or change DNS for lightsmith.dev without the owner's OK.
- Commit `.env` or real secrets; the values in `.env.example` and the compose file are for local development only.
